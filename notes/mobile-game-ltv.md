Overview
In free-to-play mobile games, player Lifetime Value (LTV) is the single most important metric for evaluating user acquisition (UA). Marketing teams must decide how much they can profitably pay for an install on each traffic source - but the true value of a user is realized over months, while UA decisions need to be made within days. The goal of this competition is to predict the long-horizon (day 180) LTV of new players using only behavioral signals from their first 7 days in the game.

Accurate early LTV predictions allow studios to:

Estimate ROAS per traffic source much earlier in the campaign lifecycle
Reallocate UA budgets toward higher-quality channels and creatives
Identify and scale acquisition of high-value player segments
Reduce reliance on slow, noisy long-window observations
Data
Participants receive a dataset of real (anonymized) player event logs covering the first 7 days after install. The event stream includes:

session_start - application launches
purchase - in-app purchases, enriched with a transaction ID
ad_impression - rewarded / interstitial / banner ad views, enriched with placement
Each event carries a timestamp and per-event attributes that allow rich behavioral features to be engineered (monetization velocity, ad engagement, retention curves, session depth, source-level patterns, etc.).

Target
For each user, predict ltv_d8_d180 - the total revenue generated by that user from day 8 through day 180 after install (in USD). Non-payers in this window have a target value of 0.

Why This Matters
Beating naive baselines on this task means the difference between scaling a profitable UA campaign and burning budget. Solutions that work well here translate directly into better unit economics for real mobile games.

About data:


Dataset Description
You are predicting the life-time value (LTV) of mobile game players based on their in-app behaviour during the first 7 days after install.

Each row in the dataset represents a single event (session start, in-app purchase, or ad impression). Multiple rows belong to the same user. Your goal is to predict - for each user in the test set - the total revenue they will generate between days 8 and 180 post-install.

What am I predicting?
ltv_d8_d180 - the total USD revenue (IAP + ad impressions) a user generates between days 8 and 180 after install. The value is 0.0 for non-paying users

Predictions should be submitted once per unique user_id in test.csv.
